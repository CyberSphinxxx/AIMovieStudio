# User acceptance scenarios

**A. Short horror 9:16:** Given 'a woman spots a shadow behind her in a foggy empty street', request Short Drama/Portrait/60 sec; app writes original script, persistent character/location references, shot storyboard, generated clips if provider ready, narrated/ambient soundtrack, valid portrait MP4, no manual prompting. Test no GPU in MOCK marked clearly, and REAL separately.

**B. Historical action 16:9:** Given a historical/martial fantasy idea, request Landscape/short movie; app generates ending, 3 act sequence, the same protagonist outfit across shots unless scene requires change; wide keyframes and final 16:9 MP4.

**C. Six-part series:** Given one concept, 6 episodes, 90 sec each, app plans complete season finale and consistent character development; first episode generated; close/restart; request next episode, story/visual voice continuity; changes to Episode 1 plot trigger future dependency warnings.

**D. Resource-limited workstation:** No video model present, show setup and a usable DEMO path; no hidden multi-GB download; 6 GB inference candidate after explicit authorization, log attempts and no more than stated retry budget; no endless busy spinner.

**E. Interrupted session:** App killed during third shot, restart from last committed output; duplicated jobs and corrupted results prevented.

**F. Rights/privacy:** No cloud transfer by default; explicit cost cap consent and rights status; no unauthorized voice clone; movie/sources remain stored locally.
